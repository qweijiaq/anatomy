## 读这份转录时要看到的

四个仓库里三个有候选，`vercel/ms` 一个都没有。这是真实的召回缺口，不掩饰：

`ms` 的设计决策是"用一张正则表把 `'2 days'` 这类字符串解析成毫秒"，代码全在 `index.js` 一个文件里，
注释是 JSDoc 风格的 `@param`，既没有 `because`/`instead of` 这类决策语言（decision-trace 抓不到），
函数名也不在"自研轮子"的词表里（custom-infra 抓不到），分支密度也没高到触发 complexity 阈值。

补法有两条，都涉及品味判断，不该在验证通道故障时顺手改掉：
1. 给 `decision-trace` 增加"密集的正则表 / 查表常量"识别；
2. 让 `complexity` 对"短小但分支密集的纯函数"更敏感。

两条都会提高假阳性，需要先在 gold 集上量一次再决定。`eval/gold/ms.json` 已经把该仓库的
三个决策标好了，`npm run eval` 就是为此准备的。
