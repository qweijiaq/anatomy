## 这轮的三条结论都有具体证据

1. **`p-debounce` 一次 3/3。** 整个库是一个闭包工厂，前缘/后缘是选项而不是两个函数——
   正是「返回函数的函数」与「决策注释」两条规则合起来能看见的形状。
2. **`p-queue` 0/3 → 2/3。** 补的两条规则都来自真实代码：
   - 一条**决策注释紧贴在某个声明上方**时，候选落在注释上、指名的却是下一行声明
     （`p-queue` 的注释解释的是 `#head`，不是整个文件）；
   - 一个**以标准算法命名的函数**（`lowerBound`）本身就是设计选择，它不属于"自研轮子"，
     所以单独给了 `algorithm` 这一类。
3. **`merge-streams` 1/3。** 剩下两处是"继承 PassThroughStream"与"用 ended/aborted 两个标记
   判断结束"，属于继承层次与状态机——现有规则只读函数体，看不见类的形状。

## 一个反向验证

`ALGORITHM_SUFFIX` 的第一版把 `rebounded` 也算成了算法（`bound` 在词中间）。测试直接抓到了：
那是常见英文动词，当成设计声明会立刻制造噪音。现在按 camelCase/下划线边界判断，
`lowerBound`、`lower_bound`、`bsearch` 命中，`rebounded` 不命中。

## 一次没有变成数字的修复

`colorette` 仍是 0/4。追下去发现是真 bug：`const replaceClose = (` 换行后 `) => …` 这种**多行箭头函数**
被判定为"不是代码"，于是整个文件——一个短箭头辅助函数加一个布尔开关构成的库——一个候选都没有。
修完之后（多行续行按首字符判定，箭头算代码、`!x && y` 算值），新加的测试钉住了两边，
但 `colorette` 的**总分没有变化**：文件名 `index.js`、没有 wheel 词、没有注释关键词，
规则看得见"它是函数"，却没有理由把它当成一个值得学的决策。

这个结果保留在数字里，没有抹掉：45% 的时候报 45%。

## 第二个真 bug：带默认对象参数的函数完全不在索引里

追 `destr` 的 0/3 时发现的，比上一个严重得多：

```js
function f(x, options = {}) { … }        // ← 这个函数根本不存在
function f(x) { … }                      // ← 这个存在
```

`jsFunctionSpans` 用「括号深度不为零就跳过 `{`」来排除对象字面量实参。但**默认参数也是花括号**，
而且它在函数体之前就闭合了 —— 于是所有带 `options = {}` 的函数都被跳过。现代 JS 库的公开 API
几乎全是这个签名。

修法是让**默认参数的花括号**与**对象实参的花括号**区分开：前者在括号之间闭合，后者不会。
三个新测试钉住它（`f(x, o = {})` 必须有候选、`f(x)` 保持有候选、字符串里的 `return` 不算护栏）。

这条修复让「护栏阶梯」规则（6 个以上早退出、120 行以内的短函数 = 决策表）真正生效，
但 `destr` 依旧是 0/3：它的 `return` 分散在 switch 与 try/catch 里，`jsFunctionSpans`
给出的 span 仍然不含全部 —— 数值照实报。
