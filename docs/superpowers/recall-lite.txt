## 这轮做的是"补语言"，不是"调规则"

`dbrgn/tealdeer`（Rust）此前召回 **0/3**，并不是规则不好——它的源码根本不在分析口径里。
补法分三处，都用近似而非解析来换诚实：

1. **近似结构索引**（`src/kernel/structure/generic.ts`）：按行首关键字识别 `fn`/`struct`/`impl`/
   `func`/`def`/`function`/`class` 等声明，覆盖 Rust、Go、C/C++/ObjC/C#、Java/Kotlin/Swift/Dart/Zig、
   Ruby/PHP/Lua。**不声明任何 import 边**——近似的边就是编造，而报告已经写明这个语言是近似读取。
2. **近似函数体**（`signals.ts` 的 `genericFunctionSpans`）：从声明行到匹配的大括号，`{` 若在声明后
   两行以外就放弃。跨语言的括号语义一致，猜错的代价是漏一个候选，不是编造一个。
3. **语言名单**：`detectLanguage` 现在认识这些扩展名，`unsupported-language` 只留给真正的未知语言
   （`.vue`、`.svelte` 这类单文件组件仍按未知计），因此报告能同时说「读了什么语言」和「哪些文件读不了」。

效果：`tealdeer` 从 0 候选到 11 个候选、1/3 命中；全局 40% → 42%。数字只涨了两个点，但**那是一个
整类仓库从"不可用"变成"可用"**。

## 仍然诚实的一件事

`src/lib.rs` 的 import 图依旧是空的，`src/kernel/structure/generic.ts` 在 notes 里明写
`approximate structure: declarations only, no import graph`。报告不会假装知道 Rust 的模块依赖。
