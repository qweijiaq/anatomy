# 质量盲评：怎么量，以及为什么现在还没法量

## 想量的是什么

产品的目标是"让人读完说'哦，原来还能这么干'"。现在我们知道它**能找到 41/90 个专家标注的决策**，
但不知道**这 41 条写出来好不好读**。这两件事完全不同：

- 召回差 → 报告像没找到东西
- 质量差 → 报告有一堆东西，但没人想看

## 为什么现在量不出来

我搭好了整个流程（`npm run eval:quality` 生成页面、`eval/quality-prompt.md` 是评分表），
但跑到最后一步卡住了，而且这个卡点是真实的、不该绕过去的：

**页面上的分析文字全部来自模型。** 我用确定性 stub 代替模型跑，得到的正文是
"待模型补全"，因为 stub 只会把引用贴上去、不会写分析。而**用"待模型补全"去评质量，
量到的是 stub 的能力，不是产品的质量**。

换成真模型可以直接量，但本机没有 provider key（`~/.x-code/desktop-secrets.json` 里只有
`deepseek` / `alibaba` / `custom` 三个，且都是加密的 `enc` 字段，不是我想动的东西）。

## 所以我把样本做成"能评的部分"和"不能评的部分"分开

`eval/quality-sample/*.md`（29 个仓库）里，**能评的是这些**：

| 维度 | 样本里能看 | 谁负责 |
|---|---|---|
| 页面结构 | 约束 / 常见做法 / 他们怎么做 / 为什么有效 / 代价 五段是否齐 | 渲染器（可以评） |
| 证据可核对 | `path:start-end` 指得准不准、片段是不是逐字原文 | 校验器（可以评） |
| 取舍意识 | 每个点是否都写了代价与"什么时候会痛" | schema（可以评） |
| 诚实度 | "没看的部分"、可信度数、被丢弃证据数 | 渲染器（可以评） |
| **分析的价值** | 这段话有没有让人"哦"一下 | **模型（评不了）** |

前四行我已经用测试钉住了（`docs/superpowers/EVIDENCE.md` 里有对应关系）。第五行只能等真模型。

## 结论：现在该做的不是换解析器

我在上一轮说"先量质量，再决定要不要为多出的 49 个点换解析器"。量完之后，这个判断变成了：

**质量的下限已经由结构和校验钉住了，而上限完全取决于模型。** 换解析器提高的是召回（41 → 或许 55），
不会提高每一条的质量。**在召回 46% 且每条质量未知的情况下，先把召回推上去是性价比更高的**——
因为召回低的时候，就算每条都写得很好，读者也只能看到项目的一半。

但还有一件事比重这些更急：**我至今没有用真模型跑过一次完整的 `ana analyze`。**
打桩测试证明了链路通、证据可核对、页面结构对，但**没有人真的读过一份真模型写出来的报告**。

## 需要你决定

1. **给我一个可用的 provider key**（或告诉我用哪个 provider），我用真模型跑 3 个仓库，
   你读那三份报告——这是唯一能真正回答"这东西值不值得做"的方式。
2. 或者先不量质量，继续推召回（46% → 更高），等有 key 再说。
3. 或者承认 MVP 到此为止，把这个状态当成交付。

我倾向 1。**因为如果真模型的输出不好读，那么无论召回是 46% 还是 80%，这个产品都不成立。**
