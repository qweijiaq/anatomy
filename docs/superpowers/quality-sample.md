# 质量盲评：怎么量，以及为什么现在还没法量

## 想量的是什么

产品的目标是"让人读完说'哦，原来还能这么干'"。现在我们知道它**能找到 41/90 个专家标注的决策**，
但不知道**这 41 条写出来好不好读**。这两件事完全不同：

- 召回差 → 报告像没找到东西
- 质量差 → 报告有一堆东西，但没人想看

## 为什么现在量不出来

我搭好了整个流程（`npm run eval:quality` 生成页面、`eval/quality-prompt.md` 是评分表），
但跑到最后一步卡住了，而且这个卡点是真实的、不该绕过去的：

**页面上的分析文字全部来自模型。** 我用确定性 stub 代替模型跑，得到的正文是
"待模型补全"，因为 stub 只会把引用贴上去、不会写分析。而**用"待模型补全"去评质量，
量到的是 stub 的能力，不是产品的质量**。

换成真模型可以直接量，但本机没有 provider key（`~/.x-code/desktop-secrets.json` 里只有
`deepseek` / `alibaba` / `custom` 三个，且都是加密的 `enc` 字段，不是我想动的东西）。

## 所以我把样本做成"能评的部分"和"不能评的部分"分开

`eval/quality-sample/*.md`（29 个仓库）里，**能评的是这些**：

| 维度 | 样本里能看 | 谁负责 |
|---|---|---|
| 页面结构 | 约束 / 常见做法 / 他们怎么做 / 为什么有效 / 代价 五段是否齐 | 渲染器（可以评） |
| 证据可核对 | `path:start-end` 指得准不准、片段是不是逐字原文 | 校验器（可以评） |
| 取舍意识 | 每个点是否都写了代价与"什么时候会痛" | schema（可以评） |
| 诚实度 | "没看的部分"、可信度数、被丢弃证据数 | 渲染器（可以评） |
| **分析的价值** | 这段话有没有让人"哦"一下 | **模型（评不了）** |

前四行我已经用测试钉住了（`docs/superpowers/EVIDENCE.md` 里有对应关系）。第五行只能等真模型。

## 结论：现在该做的不是换解析器

我在上一轮说"先量质量，再决定要不要为多出的 49 个点换解析器"。量完之后，这个判断变成了：

**质量的下限已经由结构和校验钉住了，而上限完全取决于模型。** 换解析器提高的是召回（41 → 或许 55），
不会提高每一条的质量。**在召回 46% 且每条质量未知的情况下，先把召回推上去是性价比更高的**——
因为召回低的时候，就算每条都写得很好，读者也只能看到项目的一半。

但还有一件事比重这些更急：**我至今没有用真模型跑过一次完整的 `ana analyze`。**
打桩测试证明了链路通、证据可核对、页面结构对，但**没有人真的读过一份真模型写出来的报告**。

## 这个悬而未决的问题后来怎么解决的

写上面那段时，这个项目**确实**没有用真模型跑过一次完整的 `ana analyze`。之后跑了，用的是
deepseek-v4.1-flash，仓库是 `feedback-desk`（8529 行）与 `quick-lru`（2606 行）。

读那几份报告读出的问题，全部变成了代码改动：

| 真模型报告里看到的 | 改了什么 |
|---|---|
| `problem` 只有 25 字（quick-lru），"一个小型工具库" 这种一句交差 | 综述提示加第 5 条硬性规则：80–200 字，按「是什么 / 难在哪 / 为什么值得读」组织，并点名禁止「值得学习」「设计精妙」这类空话 |
| 正文里出现 `` \`ip\|slug\` `` —— 反斜杠泄漏到页面上 | `prose()` 不再转义反引号；两条断言了错误行为的测试改成断言正确行为 |
| 「没看的部分」里写着 `synthesis chose 5 of 6 rendered points` 和 `model reported no learning point` | 改成读者能用的说法，并列出被略掉的点的标题 |
| 每点平均证据 2.29 条，但 5 条里有 2 条是"这个函数很长" | 信号层大改：`complexity` 单独命中降权，新增 security / data-integrity / resilience / idiom，`evolution` 学会读 camelCase |

也就是说：**"值不值得做"这个问题，答案不是判断出来的，是读真报告读出来的**，而且读完之后
产品确实变好了一截（同一仓库的候选从"6 条长函数"变成"7 条真决策，覆盖 4 个文件"）。

## 交付边界

写清楚，免得留下「还需要人决定」的悬空状态。**这一版交付的是：**

- 八条命令全部可用，`npm run verify` 一条命令自证（703 个测试 + 三套 tsconfig + 端到端）
- 有源码的仓库：产出带行号证据的设计笔记，验证不过的说法不进正文
- 没有源码的应用：经 REA 取证，产出事实报告与两份差异，全程不调模型
- 中文与英文的完整报告（骨架 + 正文）

**不在这一版范围内，README 的「Not built yet」逐条列着**：MCP server、`ana publish`、
TS/JS 与 Python 之外的结构分析、无源码应用的**判断版**报告（需要第二个校验器，对
`evidence_id` 而不是磁盘字节）。

召回率 60% 是这一版的实测值，也是它的已知上限——四成的专家标注点连候选都进不去。
这个数字写在 README 里，跟着这份快照一起，而不是藏在心里。
