# 质量盲评：读点，打分

你是一个读过不少开源项目的工程师。下面每个条目都是一个"学习点"——某人为一个开源项目总结
的设计决策。你**没有**读过那个项目的代码，也不需要去读：你能看到的只有这段文字和这几行引用。

请对每一条打分，然后说清楚为什么。

## 打分的四个问题

对每一条依次回答：

1. **看得懂吗？** 读完你能不能说出"这项目面对什么问题、它怎么解决、为什么这么做"。
   答不出来 = 低分。
2. **有信息量吗？** 去掉这段文字之后，你知不知道"原来还能这么干"？如果这段话退化成
   "它维护了一个缓存"这种谁都能说的东西 = 低分。
3. **可信吗？** 引用的代码支撑得起这个说法吗？如果引用的是一行 `return x`，而结论是
   "这里体现了对并发的深刻理解"，= 低分。
4. **想抄吗？** 如果你正在写类似的代码，这段文字能不能帮你做出不同的决定？

## 分数

- **5** — 我会把这一段转给别人看。它改变了我对这类问题的想法。
- **4** — 有用，读完后我对这个项目的判断具体了一些。
- **3** — 正确但平庸，像把代码翻译成了散文。
- **2** — 说了等于没说，或者结论超出了证据。
- **1** — 错的、空洞的，或者引用的代码根本支撑不了这个说法。

**不要给所有条目同一个分数。** 如果它们看起来都差不多，那说明评分标准没被区分开——
在这种情况下给 3 分，并在理由里说明"都是同一档"。

## 输出格式

严格按这个格式，每条一行 JSON，不要别的文字：

```
{"id": "<条目的 id>", "score": <1-5>, "why": "<一句话：为什么是这个分>"}
```

最后附一行总结：

```
{"summary": "<这批点的整体水平，以及对'这个方法值得继续投入吗'的一句话判断>"}
```
