# 质量盲评样本

`npm run eval:quality` 会在 `quality-sample/` 下为每个金标仓库生成一份报告：
**真实内核 + 真实渲染**，模型换成一个确定性 stub。

## 这份样本能回答什么、不能回答什么

**能回答**：页面的形状对不对——一个点有没有清晰的约束 / 常见做法 / 机制 / 代价四段，
引用是不是逐字原文、行号是否指得准，"没看的部分"是否如实、可信度数是否可读。

**不能回答**：文笔。stub 只会把占位符填进去（"待模型补全"），真模型会写真正的分析。
所以**评分时请忽略正文的占位内容，只看结构、引用和取舍**；如果连结构都不及格，
那么换真模型也好不了。

## 这 29 份是快照

它们在版本库里，是为了让不能跑脚本的人也能直接看到页面长什么样。代价是：**渲染器一旦
改变，这些文件就旧了，而没有任何检查会发现**——重跑 `npm run eval:quality`，`git diff`
为空才说明它们仍代表当前输出。

## 怎么用

1. 挑 3–5 个仓库的 `.md`
2. 用 `eval/quality-prompt.md` 的四个问题逐条打分
3. 汇总：这批点的结构水平，以及"值得为它换解析器吗"的判断
